Illustrative example 01

Asset management

Audit preparation fell from a seasonal scramble to a monthly review

Read the full example

Situation

An asset manager running about 200 controls across several fund ranges. Each control owner gathered evidence at a different time and through a different channel, and external audit requests arrived with four weeks’ notice.

Problem

Evidence was reconstructed from email and shared drives rather than retrieved. Control owners disagreed about what evidence a control should produce, so the audit preparation team spent around six weeks each year assembling packs by hand.

Approach

We mapped each control to the evidence it must generate, agreed the evidence standard with internal audit, and moved collection into the control cycle so evidence was captured as each control operated.

Workflow design

Every control record holds its frequency, owner, evidence type and test method. Owners submit evidence through Airtable Forms, which links each submission to its control record. Items that pass their due date escalate to the owner’s manager without anyone chasing them.

Automation design

Airtable Automations create evidence requests from the control calendar 14 days before each due date and run completeness checks on every submission. An Interface Designer dashboard shows control status by fund range. Record history keeps the author and timestamp for every change.

Outcomes

Audit preparation became a monthly review rather than a seasonal project. Internal audit reported fewer evidence exceptions in the following cycle, and control owners stopped receiving ad hoc requests.

Illustrative example 02

Consumer lending

Routine adverse media hits cleared 35% faster, with every AI summary traceable to a reviewer

35%Less review time on routine hits (illustrative)
4%Sampled summaries needing material correction, falling each quarter (illustrative)
100%Outputs traceable to model version and reviewer (illustrative)
Read the full example

Situation

A consumer lender used adverse media screening during onboarding, and analysts reviewed each hit by hand. An innovation team had piloted AI summaries without a governance framework, and the risk function paused the pilot until it had controls in place.

Problem

Analysts trusted the summaries without checking them, and nothing recorded which summaries had informed a decision. The use case had no named owner, no risk tier and no monitoring of error rates.

Approach

We reset the use case within the AI governance framework. We assessed the risk and assigned Tier 2, supervised use, which sets a confidence threshold and sampled review. We defined the review standard, built the monitoring, and restarted the pilot in that controlled form.

Workflow design

Each adverse media hit has its own Airtable record with a summary and source links. The analyst records a disposition and marks the summary as accepted, edited or rejected. Summaries below the confidence threshold route to a senior reviewer through a filtered view.

Automation design

A Make scenario sends each new screening hit to the OpenAI API and writes the summary to the record with status Pending review. The model name and prompt version are stored on every record. Each month a sample of dispositions is compared with the summaries they relied on.

Outcomes

The risk function approved the use case as Tier 2 with defined sampling. Analysts cleared routine hits faster, complex matches kept full review, and the use case became the reference pattern for the firm’s AI use-case register.
